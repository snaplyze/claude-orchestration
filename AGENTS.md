# Сведения о проекте

- Назначение: дистрибутив оркестрации Claude Code для пользователей подписок Pro/Max/Team/Enterprise и API — плагин `plugin/` (skill `orchestrate` + 5 подагентов), восемь профилей `profiles/`, установщик `scripts/install.py` (+ `setup.sh`/`setup.ps1`; в проект или `--user` — локальный marketplace с профилем и управляемый файл правила `rules/claude-orchestration.md` в пользовательской конфигурации Claude), runtime-проверка `scripts/runtime_smoke.py`, документация `docs/`.
- Быстрый сигнал: `python -m unittest tests.test_distribution.DistributionTests.<test>`.
- Обязательные проверки: `python -m unittest discover -v`, `python scripts/doctor.py`, `sh -n setup.sh`, `claude plugin validate --strict ./plugin` и `claude plugin validate --strict .` (нужен установленный `claude`). Перед приемкой изменений плагина или профилей — платная runtime-проверка моделей и effort ролей: `python scripts/runtime_smoke.py --skill --tool-surface --agent-path` (+ `--interactive` через tmux) под логином `claude` или workflow `runtime-smoke.yml` (секрет `CLAUDE_CODE_OAUTH_TOKEN`). Hosted Windows/macOS и runtime-smoke — перед приемкой или по риску, не на каждую правку.
- Инварианты продукта: имя плагина `orchestration` без зарезервированных префиксов (`RESERVED` в `scripts/doctor.py`); явные `model` + `effort` у skill и каждого подагента; восемь профилей с полной топологией; установщик сохраняет посторонние настройки цели, откатывается при ошибке и отвергает symlink-цели. Без равноценной замены не убираются границы доверия (путь и symlink цели, имя профиля), откат изменяемого состояния (плагин и `settings.json`) и обязательные проверки.
- Ловушки: Claude Code (≥ 2.1.277) читает этот файл, только пока в рабочем каталоге и выше нет `CLAUDE.md`, `.claude/CLAUDE.md` или `CLAUDE.local.md`, — не создавай их; личные правила — в `~/.claude/rules/`. Версионно-зависимое поведение Claude Code и моделей подтверждай первичной документацией Anthropic (`docs/research-sources.md`); права подписки не выводи из имен профилей; статические тесты не доказывают доступ к модели или inference. Не создавай `.claude/` в корне: `test_symlinks_and_unknown_profile_names_rejected` требует его отсутствия (A-23 в плане).
- Ресурсная приемка: числовых целей в требованиях нет; принятый предел — полный `python -m unittest discover` ≤ 2 с и один запуск установщика ≤ 0,2 с на машине разработчика (2026-10-13: 0,59 с на 27 тестов; установщик ~37 мс на 2026-10-09; Python 3.14). Если стоимость растет с размером входа (профили, файлы, события), меряй на 1× и 10×.
- План: `docs/plan.md` — единственный реестр и очередь (на английском; статусы READY/BLOCKED/CONFIGURED_LOCAL/DONE); описания — в `docs/`, `CHANGELOG.md` (новое сверху); публикация — GitHub issues/PR. Конкурирующие roadmap не создавай.
- CI (владелец): только GitHub-hosted (2026-10-09); подробности — `docs/verification.md`.
- CI (обнаружено, 2026-10-13): hosted — `ci.yml`: `ubuntu-latest`/`macos-latest`/`windows-latest` × Python 3.12/3.13 и 3.11 на Ubuntu, jobs `shell` и `plugin` на `ubuntu-latest`; `runtime-smoke.yml` — `ubuntu-latest`, только запуски владельца и PR из этого репозитория. Self-hosted нет: API раннеров репозитория вернул 0, владелец — пользовательский аккаунт без раннеров организации.
- Оркестрация: доступные роли `orchestration:explorer|researcher|worker|tester|reviewer` (плагин `orchestration`; у владельца — user scope, профиль `max-20x-thorough`) и встроенные подагенты; вложенность по умолчанию — 3 уровня; владелец выключает ее (подагенты не запускают подагентов) запуском `CLAUDE_CODE_MAX_SUBAGENT_SPAWN_DEPTH=1 claude`, проектная настройка — A-23.
- Решения владельца: релизы разрешены заранее (2026-10-09) — версия в `plugin.json`, датированный CHANGELOG, тег `vX.Y.Z` на merge commit, GitHub Release после принятого и проверенного блока; затем обнови пользовательскую установку (`install.py --user`) и проверь `runtime_smoke.py --use-installed`. Покупка кредитов, глобальные настройки Claude и прочее внешнее состояние, кроме публикации issue → ветка → PR → main, — только с явного разрешения. Доступ агентов — полный (2026-10-13): выбор владельца, а не безопасный стандарт. Режим `bypassPermissions` проектные настройки не задают (Claude Code игнорирует его там с 2.1.257) — только `~/.claude/settings.json` или `claude --permission-mode bypassPermissions`.
