# Сведения о проекте

- Назначение: дистрибутив оркестрации Claude Code для пользователей подписок Pro/Max/Team/Enterprise и API — плагин `plugin/` (skill `orchestrate` + 5 подагентов), восемь профилей `profiles/`, установщик `scripts/install.py` (+ `setup.sh`/`setup.ps1`; в проект или `--user` — локальный marketplace с профилем и управляемый файл правила `rules/claude-orchestration.md` в пользовательской конфигурации Claude), runtime-проверка `scripts/runtime_smoke.py`, документация `docs/`.
- Быстрый сигнал: `python -m unittest tests.test_distribution.DistributionTests.<test>`.
- Обязательные проверки: `python -m unittest discover -v`, `python scripts/doctor.py`, `sh -n setup.sh`, `claude plugin validate --strict ./plugin` и `claude plugin validate --strict .` (нужен установленный `claude`). Перед приемкой изменений плагина или профилей — платная runtime-проверка моделей и effort ролей: `python scripts/runtime_smoke.py --skill --tool-surface --capabilities --agent-path` (+ `--interactive` через tmux) под логином `claude` или workflow `runtime-smoke.yml` (секрет `CLAUDE_CODE_OAUTH_TOKEN`). Hosted Windows/macOS и runtime-smoke — перед приемкой или по риску, не на каждую правку.
- Инварианты продукта: имя плагина `orchestration` без зарезервированных префиксов (`RESERVED` в `scripts/doctor.py`); явные `model` + `effort` у skill и каждого подагента; восемь профилей с полной топологией; установщик сохраняет посторонние настройки цели, откатывается при ошибке и отвергает symlink-цели. Без равноценной замены не убираются границы доверия (путь и symlink цели, имя профиля), откат изменяемого состояния (плагин и `settings.json`) и обязательные проверки.
- Ловушки: Claude Code (≥ 2.1.277) читает этот файл, только пока в рабочем каталоге и выше нет `CLAUDE.md`, `.claude/CLAUDE.md` или `CLAUDE.local.md`, — не создавай их (чтение отключает и пользовательская настройка `/config` → Project instructions: `claude-md` или `managed-only`); личные правила — в `~/.claude/rules/`. Версионно-зависимое поведение Claude Code и моделей подтверждай первичной документацией Anthropic (`docs/research-sources.md`); права подписки не выводи из имен профилей; статические тесты не доказывают доступ к модели или inference. Проектных настроек агентов в checkout нет (решение владельца, 2026-10-15): глубина подагентов и запреты на чтение секретов задаются в пользовательских настройках; `settings.local.json` и `agent-memory-local/` в gitignore; тесты границы checkout (`test_refused_installs_write_nothing_into_the_checkout`) работают с временной копией checkout, а не с рабочим каталогом.
- Ресурсная приемка: числовых целей в требованиях нет; принятый предел — полный `python -m unittest discover` ≤ 2 с и один запуск установщика ≤ 0,2 с на машине разработчика (2026-10-13: 0,18–0,20 с на 29 тестов при 3 subprocess-запусках — один сквозной запуск установщика, проверка fixture и hook-скрипт, см. A-38; установщик ~38 мс; Python 3.14). Если стоимость растет с размером входа (профили, файлы, события), меряй на 1× и 10×.
- План: `docs/plan.md` — единственный реестр и очередь (на английском; статусы READY/BLOCKED/CONFIGURED_LOCAL/DONE); описания — в `docs/`, `CHANGELOG.md` (новое сверху); публикация — GitHub issues/PR. Конкурирующие roadmap не создавай.
- CI (владелец): только GitHub-hosted (2026-10-09); подробности — `docs/verification.md`.
- CI (обнаружено, 2026-10-15): только hosted — `ubuntu-latest`, `macos-latest`, `windows-latest` (матрицы `ci.yml` и `runtime-smoke.yml`, переиспользуемых workflow нет); self-hosted нет: API раннеров репозитория вернул 0, владелец — пользовательский аккаунт без организаций. Триггеры и условия — `docs/verification.md`, раздел GitHub Actions.
- Оркестрация (обнаружено, 2026-10-21): роли `orchestration:explorer|researcher|worker|tester|reviewer` и skill `orchestration:orchestrate` (плагин `orchestration` 1.7.0, профиль `max-20x-thorough`, правило `rules/claude-orchestration.md`) — только в пользовательской конфигурации владельца, другим участникам недоступны; встроенные подагенты Claude Code (Explore, Plan, general-purpose и др.) есть у всех; в проекте ролей, навыков и настроек подагентов нет; глубина вложенности нигде не задана (по умолчанию 3 уровня).
- Доступ (обнаружено, 2026-10-15): `bypassPermissions` без подтверждения — только в пользовательских настройках владельца, в проекте и управляемых настройках режима нет; секреты: чтение не запрещено — `permissions.deny` нет ни в одной области (фиктивный `.env` прочитан через `Read`).
- Решения владельца: релизы разрешены заранее (2026-10-09) — версия в `plugin.json`, датированный CHANGELOG, тег `vX.Y.Z` на merge commit, GitHub Release после принятого и проверенного блока; затем обнови пользовательскую установку (`install.py --user`) и проверь `runtime_smoke.py --use-installed`. Покупка кредитов, глобальные настройки Claude и прочее внешнее состояние, кроме публикации issue → ветка → PR → main, — только с явного разрешения. Доступ агентов — полный (2026-10-13): выбор владельца, а не безопасный стандарт. Режим `bypassPermissions` проектные настройки не задают (Claude Code игнорирует его там с 2.1.257) — только `~/.claude/settings.json` или `claude --permission-mode bypassPermissions`.
